What is salting?

One widespread method that is very effective against dictionary attacks is so-called salting.

Here, a random block of text (salt) is appended to the password before it is hashed. This produces a hash value that is unique to the combination of password and salt.

In the widget, we can generate salts by adding any sequence of letters and numbers in the key node.

So that the website can check the password at the next login, the salt is stored in the database together with the hash. When logging in, the entered password is simply combined with the stored salt and hashed again. If the results match, the password is correct.

But how secure is that? Could hackers not then simply try everything out again?

Salting helps above all against large lists of prepared passwords or already computed hash tables (rainbow table). It ensures that even if two people use the same password (e.g. “Sunshine123”), their hash values in the database look completely different.

However, salting alone does not protect against pure and slow “trying everything out” (brute force). That is why many websites additionally use special hash functions that deliberately take a lot of time.
